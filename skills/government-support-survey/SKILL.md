# 정부지원 공고 조사

5개 공개 포털의 모집 공고 메타데이터(제목·분야·주관기관·접수기간·공식 URL)를 한 형식으로 모은 뒤, 사용자의 사업 조건과 대조해 후보를 분류한다. 조회와 판정까지만 하며 신청은 사용자가 공식 사이트에서 한다.

출처: [NomaDamas/k-skill](https://github.com/NomaDamas/k-skill) `government-support-survey` (커밋 `283388095e2b1a784b6f5c04bed570174f45edf4`, MIT, 같은 폴더의 `LICENSE`). 조사 로직의 원 출처와 데이터 재배포 범위는 [references/NOTICE.md](references/NOTICE.md)에 있다.

## 데이터 경로

`scripts/run_survey.py`는 표준 라이브러리만 쓰며 `https://k-skill-proxy.nomadamas.org/v1/government-support/survey`를 호출한다. 이 프록시는 제3자 운영 서버이므로 **검색 조건(출처 목록, 키워드, 페이지 수)이 그 서버로 전달된다**. 키워드에는 공고 검색에 필요한 일반 용어(예: `AI 바우처`, `콘텐츠 제작`)만 넣고, 회사명·매출·대표자 정보·사업계획 내용은 넣지 않는다. 사업 조건 대조는 받은 결과를 로컬에서 한다. 다른 프록시를 쓸 때만 `--proxy-base-url` 또는 `KSKILL_PROXY_BASE_URL`을 지정한다. 사용자 API 키는 필요 없다.

## 실행

이 SKILL.md가 있는 폴더를 `$skillDir`로 정하고, 실제 Python 실행 파일을 확인해 `$pythonExe`로 사용한다. Windows에서는 Store 실행 별칭을 정상 인터프리터로 가정하지 않고 UTF-8 모드로 실행한다.

```powershell
& $pythonExe -X utf8 (Join-Path $skillDir 'scripts/run_survey.py') --keyword 'AI 바우처' --compact
```

- `--sources`: `kstartup bizinfo nipa kocca smtech` 중 선택(기본 전부). 사용자가 기관을 지정하면 그 범위로 좁힌다.
- `--max-pages`: 출처별 조회 페이지 수, 기본 1, 허용 1~10.
- `--per-page`: 1~100, 기본 100.
- `--keyword`: 생략하면 키워드 필터 없이 조회한다.

종료코드는 `complete=true`이면 0이고, 일부 출처 실패나 HTTP·네트워크 오류면 2다. 종료코드 2에서도 stdout에 JSON이 있으면 부분 결과다. stdout 없이 stderr만 있으면 조회 실패다.

## 결과 해석

- `complete`는 요청한 출처가 모두 정상 응답했다는 뜻이다. 조회한 페이지 범위 안의 결과이므로 해당 기관의 모든 공고를 망라했다는 보장은 아니다.
- `sources`에서 출처별 `ok`, 조회 페이지, 수집 건수, 오류를 확인한다. 실패한 출처는 누락으로 명시한다.
- `0 items parsed; site layout may have changed`는 파서 문제일 수 있으므로 해당 출처를 성공으로 보지 않는다.
- K-Startup 키가 프록시에 없으면 그 출처만 빠진다. 나머지 결과는 유지하고 누락을 밝힌다.
- `401/403`, 차단, CAPTCHA, 로그인, 본인인증이 나오면 우회하지 않고 공식 사이트 확인을 안내한다.
- `items`의 필드는 `source`, `id`, `title`, `field`, `org`, `apply_start`, `apply_end`, `reg_date`, `url`이다. 마감된 공고도 섞일 수 있으므로 KST 기준 현재 날짜와 비교하고 공식 공고의 마감 시각·변경 공지를 우선한다. 날짜가 없거나 불명확하면 접수 중으로 단정하지 않는다.

보고에는 조회한 출처, 키워드, 출처별 조회 페이지 수, 조회 시각을 밝힌다. 범위가 부족해 보이면 같은 조건으로 페이지 수나 키워드를 넓혀 다시 조회할 수 있지만, 사용자가 요청한 범위를 넘는 전체 조사로 키우지 않는다.

## 적합성 판정

판정은 `즉시 지원 가능`, `요건 충족 시 가능`, `사업 변형 시 가능`, `부적합` 네 단계로 보수적으로 한다.

- 판정에는 업력, 소재지, 업종·기술, 대표자 연령, 기업 형태, 매출·투자 단계, 원하는 지원 유형이 필요하다. 대화나 작업 공간에서 이미 알 수 있는 조건은 그대로 쓰고 다시 묻지 않는다.
- 모르는 조건은 지어내지 않는다. 판정 근거에 `확인 필요: <조건>`으로 남기고, 알려진 조건만으로 판단할 수 있는 후보는 계속 진행한다. 판정 전체가 한 조건에 달려 있을 때만 그 조건을 묻는다.
- 제목만으로 자격을 확정하지 않는다. 상위 후보는 공식 상세 URL과 첨부 공고문에서 신청대상, 제외조건, 지역, 업력, 중복수혜 제한을 확인한다. 원문을 확인하지 못한 후보는 그 사실을 표시한다.
- 후보마다 공식 URL, 접수 마감일, 판정 근거, 남은 확인사항을 적는다.

신청·제출·계정 로그인은 이 스킬 자체의 범위가 아니다. 사용자가 실제 신청까지 요청하면 해당 작업으로 전환하고 기존 승인 범위를 따르며, 이 조회 스킬의 실행을 제출 승인으로 간주하지 않는다.

## 재배포 범위

공고 본문과 첨부파일은 기관마다 이용조건이 다르다. 프록시는 메타데이터와 공식 링크를 제공한다. 적합성 판단에 필요한 공식 원문·첨부는 허용된 경로로 읽고 근거를 요약하되, 원문 전체의 미러링·재배포를 조회와 혼동하지 않는다.
