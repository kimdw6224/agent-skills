# 기존 UI를 다듬는 기준

요청한 화면·컴포넌트와 실제로 영향을 받는 상태에 필요한 항목만 적용한다. 아래 목록은 모든 작업에서 전부 실행하는 절차가 아니다.

## 수정의 기준

- 현재 코드, 렌더 화면, 토큰과 공통 컴포넌트에서 기존 브랜드·동작·실제 문구를 파악한다. `DESIGN.md`가 없어도 일관된 제품을 새 디자인의 빈 도화지로 취급하지 않는다.
- 문제를 기존 값의 잘못된 사용, 공통 컴포넌트 누락, 정보·흐름의 불일치, 개별 구현 결함 중 어디에서 생겼는지 구분하고 원인을 가장 좁은 범위에서 고친다.
- 잘 작동하는 스타일·행동과 사용자 편집을 보존한다. 기능·사실·카피를 바꿔야 한다면 요청과 기존 승인 범위를 따른다.
- 같은 화면의 여러 문제가 있으면 작업을 막는 기능 결함 → 로딩·빈 결과·오류 등 상태 → 정보 흐름·레이아웃·타이포·반응형 → 세부 표현 순으로 중요도를 판단한다. 특정 항목의 완벽함을 위해 더 큰 사용 문제를 남기지 않는다.

## 흐름과 상태

- 사용자가 현재 상태와 다음 행동을 알아볼 수 있는지 본다. 버튼 이름, 저장 방식, 취소·복귀 흐름은 인접 화면의 관례와 맞춘다.
- 로딩, 빈 목록, 검색 결과 없음, 오류, 성공, 비활성, 읽기 전용 중 해당 기능이 실제로 가질 상태를 구분한다. 빈 결과를 오류처럼, 실패를 성공처럼 표시하지 않는다.
- 오류에는 무엇이 실패했고 사용자가 무엇을 할 수 있는지 적는다. 폼 오류가 나도 입력을 보존하고 문제가 있는 필드와 설명을 연결한다.
- 느린 요청이 있는 동작은 진행 중임을 알리고 중복 실행이 실제로 문제가 되는 경우 중복 제출을 막는다. 요청 완료·실패·취소 후 조작이 다시 가능한지도 본다.
- 여러 요청의 응답 순서가 화면을 뒤집거나 오래된 상태를 덮는 문제가 확인되면 기존 상태 관리 방식 안에서 고친다. 검증 없이 자동 재시도·낙관적 갱신·오프라인 모드를 추가하지 않는다.

## 레이아웃과 타이포그래피

- 주된 작업·정보, 보조 정보와 관련 그룹이 시선 순서에서 구별되는지 본다. 모든 내용을 같은 카드·크기·강조로 평준화하지 않는다.
- 기존 그리드·간격·정렬을 기준으로 수학적 위치와 눈에 보이는 무게를 함께 맞춘다. 일회성 간격 하나 때문에 새 토큰 체계를 만들지 않는다.
- 작은 화면, 중간 폭, 넓은 화면 중 변경이 영향을 주는 조건을 확인한다. 고정 폭·최소 폭·중첩 컨테이너가 불필요한 가로 스크롤이나 겹침을 만드는지 본다.
- Flex/Grid 내부 텍스트가 줄어들지 않는 문제는 해당 자식의 `min-width`, 콘텐츠 폭과 overflow 조건부터 확인한다. 일괄 `overflow: hidden`으로 중요한 내용과 포커스 표시를 잘라 문제를 숨기지 않는다.
- 같은 역할의 글꼴·크기·굵기·행간을 일관되게 쓰고 실제 내용 길이와 확대 상태에서 읽히는지 본다. 기존 글꼴을 바꾸는 것을 개선의 기본값으로 삼지 않는다.
- 이미지의 화면 비율·표시 영역을 유지하고 로딩 중 레이아웃이 튀지 않게 한다. 아이콘은 기존 계열과 선 굵기를 따른다.

## 한글·긴 문구·없는 데이터

- 실제 제품에서 가능한 긴 이름·제목·번역문, 빈 값, 숫자 0과 큰 값을 사용해 확인한다. 테스트용 글자 수나 항목 수를 모든 제품의 요구사항으로 고정하지 않는다.
- 한글·CJK·이모지가 깨지지 않고 선택한 폰트에서 표시되는지 확인한다. 한글 문장과 혼합 영문·숫자의 줄바꿈을 보며, 의미를 알아야 하는 문구를 무조건 말줄임하지 않는다.
- 줄바꿈·말줄임·펼쳐 보기 중 정보의 용도와 기존 인터랙션에 맞는 방법을 택한다. 설명·오류·금액·필수 조건을 잘라야 하는 선택은 다시 판단한다.
- 고정 높이·폭의 버튼과 입력 영역에서 긴 라벨, 오류 메시지, 폰트 로딩과 텍스트 확대가 주변 요소를 밀거나 가리지 않는지 본다.
- 빈 값·없음·0을 의미에 맞게 구분한다. 날짜·시간·금액은 제품의 기존 로캘과 시간대 기준을 따르고, 표시값을 만들거나 임의 반올림해 사실을 바꾸지 않는다.
- 지원 언어에 필요한 경우에만 RTL·복수형·로캘별 형식을 다룬다. 한국어 UI 수정에 다국어 라이브러리나 새 언어 지원을 추가하지 않는다.

## 키보드·포커스·터치

- 실제 버튼·링크·입력에 의미에 맞는 요소와 접근 가능한 이름을 사용한다. 입력 라벨·도움말·오류·비활성 이유를 해당 조작과 연결한다.
- 키보드 이동 순서가 화면의 작업 순서와 맞고 포커스가 보이는지 확인한다. 기존 모달은 열기·닫기·포커스 복귀를 확인하되 단순 작업을 새 모달로 바꾸지 않는다.
- 중요한 상태를 색만으로 구별하지 않게 하고 텍스트·컨트롤·포커스의 대비를 실제 배경과 상태에서 본다. 정적 검사 결과와 렌더 화면의 판단을 구분한다.
- 터치에서 누를 수 있는 영역과 이웃 요소 간격을 확인한다. 모바일 폭의 스크린샷만으로 실제 탭·드래그가 작동한다고 보고하지 않는다.
- 사용자 정의 드래그·슬라이더를 수정했다면 포인터 취소, 캡처 손실, 바깥에서 놓기 등 관련 중단 상황에서 고정된 드래그 상태가 남지 않고 다음 조작이 되는지 본다.
- 모션은 상태 변화를 이해하게 하고 조작·읽기를 막지 않게 한다. 기존 reduced-motion 처리를 존중하며 꾸밈을 위한 애니메이션을 추가하지 않는다.

## 요청이 감사·검토인 경우

관찰한 위치, 실제 영향, 근거, 필요한 수정 방향을 중요도 순으로 전달한다. 재현한 기능 결함, 소스에서 의심한 문제, 시각적 판단과 자동 검사 경고를 구별한다. 오탐이나 기존 의도와 충돌하는 권고는 그대로 적용하지 않는다. 임의 종합 점수나 별도 장문 보고서를 완료 조건으로 만들지 않는다.

## 구현 완료 후 확인

요청한 수정이 모두 끝나면 관련 기존 테스트와 실행 화면의 영향을 받은 경로를 확인한다. 문제에 따라 긴 문구·빈 결과·느린 응답·키보드·터치 등 필요한 상태만 포함한다. 새 기능, 다크 모드, 전체 브라우저 조합을 검사를 이유로 추가하지 않는다.

자동 검사의 깨끗한 결과는 실제 상호작용이나 좋은 디자인의 증명이 아니다. 반대로 미적 경고 하나만으로 기존 디자인을 교체하지 않는다. 실행·화면·입력을 확인할 수 없으면 확인한 소스 범위와 남은 한계를 밝힌다.

실패가 있으면 기록 확인 → 원인 수정 → 영향받은 검사 재실행으로 처리한다. 관련 검사가 통과하면 별도의 최종 리뷰나 추가 라운드를 이어 붙이지 않는다. 결과에는 바뀐 동작·표현, 실제 수행한 확인과 미확인 항목만 간단히 남긴다.
