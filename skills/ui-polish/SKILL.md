# UI 품질 점검과 다듬기

Impeccable의 audit·polish·harden에서 기존 UI 개선에 필요한 부분을 선별했다. 요청한 화면·기능의 실제 사용성을 개선하며, 기존 브랜드·구성 의도·동작·사실 카피와 다른 작업자의 변경을 보존한다.

## 작업 범위

- 점검만 요청하면 확인한 문제와 영향·위치·수정 방향을 전달한다. 수정을 요청하면 해당 범위의 문제를 실제로 고친다. 작은 간격 수정에 전체 앱 점검을 추가하지 않는다.
- 기존 화면·공통 컴포넌트·토큰·코드를 기준으로 삼는다. PRODUCT.md나 DESIGN.md가 없어도 작업할 수 있고, 이 스킬 때문에 새 설정집이나 디자인 시스템을 만들지 않는다.
- 기능을 막는 문제, 상태 전달, 정보 위계와 반응형, 시각적 불일치 중 이번 요청에 영향을 주는 층을 먼저 다룬다. 필요한 상세 항목만 [품질 기준](references/quality-checks.md)에서 읽는다.
- 신규 시각 정체성·전면 재설계는 기존 `frontend-design`의 영역이다. 타이포그래피·모션·성능만의 작업은 해당 전문 스킬을 필요한 경우에만 보완한다. 여러 스킬이나 고정 인원의 검토를 연쇄 실행하지 않는다.

## 점검에서 수정으로

실제 사용자 경로와 대표 상태를 보고 문제가 있는 원인을 좁힌다. 기존 컴포넌트·스타일에서 가장 좁고 올바른 위치를 고친다. 이미지로 보이는 증상과 코드에서 추정한 위험, 실행으로 확인한 오류를 구분한다.

모든 값의 토큰화, 일괄 폰트 교체, 다크 모드·다국어·자동 재시도 추가를 품질의 기본 조건으로 삼지 않는다. 정한 브랜드나 화면 목적에 맞는 요소를 유행 패턴이라는 이유만으로 없애지 않는다. 필요한 복잡성과 설명을 보존한다.

## 선택적으로 쓰는 검사기

정적 코드의 반복 패턴을 점검할 때 [로컬 detector](scripts/detect.py)를 사용할 수 있다. 모든 UI 수정에 필수로 실행하는 절차는 아니다.

- Windows x64 엔진 `0.1.17`이 이 스킬의 `scripts/bin/windows-x64/impeccable.exe`에 포함돼 있다. 배포자의 SHA-256 sidecar와 대조해 설치했다. 검사기 자체는 API 키가 필요 없다.
- `detect.py`는 Python 표준 라이브러리로 이 바이너리의 **detect 명령만** 호출한다. 하위 프로세스에 `DO_NOT_TRACK=1`과 `IMPECCABLE_NO_TELEMETRY=1`을 설정한다. 바이너리가 없으면 다운로드·설치 대신 오류로 끝난다.
- 자동 훅, 브라우저 확장, live 서버, 스타일 후보 추첨, 패키지·스킬 자동 갱신은 이 설치에 포함하지 않는다. 원본 `impeccable install`, `init`, `roll`, `live`, `update` 절차를 따를 필요가 없다.
- 스크립트와 엔진 경로는 이 SKILL.md가 있는 폴더 기준으로 해석한다. 실제 Python 실행 파일을 확인하고 Windows에서는 UTF-8 모드로 실행한다.

```powershell
& $pythonExe -X utf8 (Join-Path $skillDir 'scripts/detect.py') --json 'C:\project\app\src\components\Card.tsx'
```

작업 디렉터리는 대상 프로젝트에 두고 파일·디렉터리를 명시한다. 기본 검사에서 기존 DESIGN.md와 프로젝트의 의도적 예외 설정을 존중한다. `--no-config`는 설정을 배제한 독립 재현·도구 시험에만 사용한다. 새 ignore 파일을 만들어 경고를 일괄 숨기지 않는다.

### 결과 해석

- JSON 결과는 `Finding[]` 배열이다. 종료코드 **0**은 primary 문제 없음(advisory가 있을 수 있음), **2**는 primary 문제 검출, **1**은 운영 실패다. 실행 실패를 빈 결과·정상 UI로 해석하지 않는다.
- 각 항목의 실제 파일·위치·조건을 확인한다. CSS 계산식·미디어 쿼리·동적 클래스·프레임워크 분석 등에서 오탐이나 누락이 있을 수 있다. 제안된 변경을 자동으로 전부 적용하지 않는다.
- HTML 소스와 TSX·CSS의 부분 정적 분석은 실제 렌더·접근성·성능 검증과 범위가 다르다. 정적 결과가 깨끗하다는 이유로 화면이나 사용자 경로까지 통과했다고 하지 않는다.
- 렌더 대상 URL·CDP 검사 등 추가 옵션은 실제 지원 인자를 `--help`로 확인하고, 요청한 대상과 접근 범위에서만 사용한다. 정적 점검을 위해 브라우저·서버를 새로 띄우지 않는다.

## 구현 후 확인과 종료

요청된 수정을 모두 끝낸 뒤 관련 기존 테스트와 영향받은 화면·상태를 실제로 확인한다. 기존 테스트나 이미 수행한 검사가 같은 변경을 검증했다면 재사용한다. detector를 썼더라도 별도 최종 리뷰나 전체 재검사 단계를 추가하지 않는다.

렌더 확인은 바뀐 내용이 읽히고, 주요 경로가 동작하며, 필요한 키보드·화면 크기·긴 내용에서 문제가 없는지에 맞춘다. 실행할 수 없는 경우 실제로 확인한 코드 범위와 미확인 항목을 밝힌다. 관련 검사가 통과하면 완료한다.

결과는 중요한 변경 또는 발견 사항, 실제 수행한 검사와 한계만 간결하게 전달한다. 고정 점수표·전문 보고서·질문으로 끝내기·별도 기록 파일을 강제하지 않는다.
