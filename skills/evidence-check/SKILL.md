# 주장과 근거 대조

제시된 주장을 어디까지 믿을 수 있는지 밝히고, 근거가 허용하는 최소 수정문을 제안한다.
자료를 확인한 사실과 그 자료의 내용이 참이라는 판단을 구분한다.

## 대상과 범위

- 사용자 문서·문장·표에서 확인할 대상과 판단에 필요한 시점을 파악한다.
- 인용 정확도만 요청했다면 전체 사업성·연구방법·문장 품질 평가로 확대하지 않는다.
- 제공 자료만 사용하거나 웹 검색을 하지 말라는 조건을 지킨다. 그 조건에서 알 수 없는 것은 미확인으로 남긴다.
- 원문 확인이 필요하면 해당 주장에 필요한 자료만 추가로 찾는다. 새로운 시장조사나 전면 문헌조사로 확장하지 않는다.
- 별도 검증 문서나 로그를 기본으로 만들지 않는다. 기존 문서와 응답으로 충분하면 거기서 마친다.

## 주장별로 필요한 증거 찾기

- 한 문장에 여러 사실이 있으면 각각 대조할 수 있는 단위로 나눈다.
- 결론·구매·출시·설계 판단을 바꾸는 핵심 주장, 수치, 직접 인용부터 살핀다.
- 사실, 해석, 예측, 제안을 구분한다. 제안을 사실처럼 증명하려 하지 않는다.
- 주장마다 제시된 출처와 실제 확인한 근거 위치를 연결한다. 근거가 없는 연결은 추정으로 남긴다.
- 검색 결과 요약이나 다른 보고서의 재인용은 원문을 찾는 단서로 쓴다. 원문을 읽은 것처럼 표시하지 않는다.
- 공식 발표는 발표 내용의 근거가 될 수 있지만 독립적인 성능 검증이나 사용자 만족의 증거는 아니다.
- 같은 보도자료·데이터·연구를 되풀이한 여러 페이지는 독립 근거 여러 개로 세지 않는다.
- 저자 자기홍보, 판매·후원 관계, 자기 제품을 함께 추천하는 후기는 판단에 영향을 주는 경우 밝힌다.
- 원문을 확보하지 못했거나 접근이 막혔다면 확인한 자료의 범위와 부족한 원문을 명시한다.

## 원문과 의미 대조

관련 항목만 적용하고, 주장과 무관한 항목까지 체크리스트로 채우지 않는다.

- **범위:** 특정 기능·버전·지역·고객군의 결과를 전체 제품이나 모든 사용자에게 확대했는가.
- **시점:** 발표일, 조사 기간, 측정 시점, 업데이트일을 혼동했는가. 과거 성과를 현재 상태로 제시했는가.
- **수치:** 단위·통화·기간·기준값·분모가 일치하는가. 비율과 퍼센트포인트, 누적과 기간값을 구분했는가.
- **대상:** 모집단과 표본, 응답자와 전체 사용자, 유료 고객과 가입자 등 서로 다른 집단을 섞었는가.
- **조건:** 비교 기준·가격제·실험 환경·제외 조건이 빠져 의미가 바뀌었는가.
- **추론:** 관찰된 연관성을 인과관계로, 한 사례를 일반적 효과로, 예측을 확정된 결과로 옮겼는가.
- **연구:** 방법·표본·대조군·불확실성이 그 결론을 허용하는가. 통계적 유의성과 실제 효과 크기를 혼동했는가.
- **실행:** README 설명, 개발자 발표, 사용 후기, 직접 실행 결과, 독립 재현을 구분했는가.
- **확신:** 근거의 직접성·독립성·일관성·최신성을 설명한다. 산출 근거 없는 신뢰도 백분율이나 점수는 만들지 않는다.

서로 다른 출처가 충돌하면 날짜·정의·대상·방법 차이를 먼저 확인한다.
최신 자료라는 이유만으로 과거 시점의 주장에 적용하거나, 다수결로 결론을 정하지 않는다.

## 직접 인용과 논문 인용

- 직접 인용은 원문에서 해당 문자열을 검색하고 앞뒤 문맥까지 읽는다.
- 의미가 비슷하거나 단어 일부가 겹친다는 이유로 인용 확인을 선언하지 않는다. 60% 어절 일치 같은 기준도 정확 인용 검증을 대신하지 못한다.
- 인용의 일부 생략·대괄호 보충이 있다면 표시가 분명하고 원뜻을 바꾸지 않았는지 확인한다.
- 줄바꿈·공백 같은 표시 차이와 단어·수치·부정어 변경을 구분한다. OCR 결과만으로 불일치가 의심되면 가능한 범위에서 원본 페이지를 확인한다.
- 번역문은 원문과 의미를 대조하고 번역 인용임을 밝힌다. 원문과 문자 그대로 일치했다고 표현하지 않는다.
- 불일치한 문장을 원문에 맞게 몰래 고친 뒤 기존 인용이 정확했다고 보고하지 않는다. 원래 문제와 제안하는 교정을 구분한다.
- DOI·저자·제목·연도 일치는 문헌의 신원 확인이다. 그 논문이 해당 주장을 지지하는지는 본문의 결과·조건과 별도로 대조한다.
- 초록만 읽었다면 초록 범위의 확인이라고 적는다. 초록에 없는 실험 세부나 전체 결론을 검증했다고 하지 않는다.
- 필요한 경우 수정·철회·후속 출판 여부를 확인하되, 실제 확인한 판본과 시점을 남긴다.

## 판정과 최소 수정

상황에 맞는 표현을 쓰되, 판정 이유를 확인한 자료와 연결한다.

- **지지:** 확인한 근거가 해당 범위·시점의 주장을 직접 뒷받침한다.
- **부분 지지:** 핵심 일부는 맞지만 적용 범위·강도·조건을 줄여야 한다.
- **미확인:** 판단에 필요한 원문·자료가 없거나 현재 자료로 구분할 수 없다.
- **반박:** 비교 가능한 조건의 근거가 주장과 실제로 모순된다.

자료를 찾지 못한 것은 반박이 아니다. 출처가 존재하는 것만으로 지지 판정을 내리지 않는다.
문장의 참·거짓과 인용의 정확성이 다를 수 있으므로 필요하면 따로 설명한다.
수정문은 근거가 있는 핵심을 보존하고 과장된 범위·시점·확신만 줄인다. 근거 없는 대체 사실을 넣지 않는다.

## 결과 전달과 파일 수정

- 결론을 바꾸는 오류와 유지해도 되는 핵심 내용을 먼저 짧게 알린다.
- 여러 주장이라면 `원래 주장 | 판정·이유 | 근거 URL·위치 | 최소 수정문` 표가 유용하다. 한 주장에는 짧은 문단으로 충분하다.
- 위치는 자료에 맞게 페이지·표·절·타임스탬프·파일 줄을 적는다. 확인하지 않은 위치를 만들지 않는다.
- 확인 기준일이나 제공 자료의 날짜를 적어 최신성의 유효범위를 드러낸다. 최신 자료를 조회하지 않았다면 현재 상태까지 확인했다고 하지 않는다.
- 남은 미확인 사항은 무엇을 확보하면 판단할 수 있는지와 함께 적는다. 같은 확인을 형식적으로 반복하지 않는다.
- 검토 요청은 기본적으로 읽기 전용이다. 사용자가 문서 수정까지 요청했다면 승인된 범위의 실제 파일에 교정하고 변경 위치를 알린다.
- 파일을 바꾸지 않고 수정문만 제안했다면 적용 완료라고 말하지 않는다. 외부 게시·발송은 문서 교정과 별도 범위다.

## 참고한 원문과 채택한 개념

아래는 설계 참고 자료이며 실행 의존성이나 매번 읽어야 하는 절차가 아니다. 지침은 이 목적에 맞춰 새로 작성했다.

- [phuryn/pm-skills #59](https://github.com/phuryn/pm-skills/issues/59): 인터뷰 인용이 후속 문서로 전파되기 전에 원문과 대조한다는 문제의식. 제안된 부분 단어 일치 기준은 채택하지 않았다.
- [K-Dense scientific-critical-thinking](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-critical-thinking/SKILL.md): 주장 단위·대상·비교·측정 조건을 유지하고 증거 누락과 반증을 구분한다.
- [K-Dense citation-management](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/citation-management/SKILL.md): 식별자와 서지 정보를 원 기록에 대조하며 누락 정보를 만들어 채우지 않는다.
- [TheGoat395 deep-research](https://github.com/TheGoat395/Codex-Skills/blob/main/skills/deep-research/SKILL.md): 주장에 정확히 대응하는 근거, 반대 증거와 미확인 범위를 구별한다. 별도 실행 도구나 반복 검토 단계는 가져오지 않았다.
