# 영상 편집과 출력

실제 소스와 사용자의 편집 의도에서 출발해 재생 가능한 파일까지 완성한다. 편집 판단은 장면의 정보·행동·감정에 근거하고, 파일 처리는 기존 프로젝트 도구나 함께 제공한 FFmpeg 스크립트로 수행한다.

## 적용 범위

- 기존 렌더러·스타일·음성·자막 타이밍과 사용자 편집을 먼저 재사용한다. 이 스킬을 사용한다고 제작 엔진, 프레임률, 음성, 음악이나 폰트를 교체하지 않는다.
- 수정 요청은 해당 구간과 효과에 한정한다. 모션만 바꾸는 요청이면 음성과 장면 경계를 유지한다. 출력만 바꾸는 요청이면 대본·편집 의도를 바꾸지 않는다.
- 필요한 소스가 없으면 무엇이 필요한지 밝히고 준비된 부분을 진행한다. 계획·빈 타임라인·프롬프트를 완성 영상이라고 부르지 않는다.
- 컷 선택·자료화면·자막 리듬 판단이 필요하면 [편집 연출 기준](references/editing-craft.md)을 읽는다. 이야기 개발은 기존 극작 스킬, 영상 구성은 `video-plan`, 샷 설계는 `video-storyboard`를 필요할 때만 보완한다.

## 소스에서 편집으로

1. 요청과 프로젝트의 최신 편집안에서 입력, 변경 구간, 목적, 출력 위치를 파악한다. 길이·코덱·해상도·프레임률·오디오 등 파일에서 알 수 있는 값은 `probe.py`나 기존 도구의 측정값으로 확인한다.
2. 컷·리프레임·자막 판단에 필요한 프레임을 직접 보고, 실제 발화·동작의 입출점을 잡는다. 자료화면은 설명하는 사실과 대응시킨다. 화면비 변경 시 주요 인물·제품·텍스트가 남는지 판단한다.
3. 편집을 실행한다. 직접 요청된 결과까지 이어가며, 모든 작업에 중간 미리보기 승인이나 고정 단계 수를 요구하지 않는다. 긴 인코딩의 옵션이 불확실하면 해당 명령의 `--dry-run --json`을 활용한다.
4. 마지막 편집까지 끝낸 뒤 변경 범위에 맞는 실제 출력 확인을 한 번 수행한다. 실패하면 해당 원인을 고치고 영향받은 검사만 다시 실행한다.

길이를 줄이는 방법은 의미가 다르다. 대사 삭제·배속·여백 제거를 동일한 결과로 취급하지 않는다. 사용자의 의도를 추론할 수 없고 의미가 달라지는 선택만 짧게 확인한다. 게시 플랫폼이 정해졌어도 특정 음량·자막·CTA나 화면 자르기를 일률적으로 강제하지 않는다.

## 로컬 실행

`scripts/`는 이 SKILL.md와 같은 폴더에 있다. 현재 설치 경로에서 해석하며 `.claude/skills`나 `.agents/skills`를 가정하지 않는다.

- Python 3.10+와 로컬 `ffmpeg` / `ffprobe`가 필요하다. 기본 도구는 Python 표준 라이브러리를 사용한다. Windows에서는 실제 Python 실행 파일을 사용하고 Store 실행 별칭을 정상 인터프리터로 착각하지 않는다.
- 실행할 스크립트의 `--help`에서 지원 인자를 확인한다. PowerShell 예시는 `& $python -X utf8 (Join-Path $skillDir 'scripts/cut.py') $inputPath --start 1 --end 5 -o $outputPath --json-brief`이다. 변수는 실제 확인한 경로로 정한다.
- 파일·필터·코덱 오류가 나면 오류가 가리킨 조건부터 확인한다. `_contract.py doctor --json`은 설치 상태 질문이나 실제 환경 오류 진단에 사용한다. 매 작업의 선행 절차로 만들지 않는다.
- 대부분의 쓰기 도구는 `-o`, `--json-brief`, `--timeout`, `--fast`, `--dry-run`을 지원한다. 개별 지원 여부는 도움말로 확인한다. 측정 도구는 dry-run에도 디코딩·측정을 할 수 있고 `verify.py`는 dry-run을 무시한다. 이를 무실행 모드라고 설명하지 않는다.
- 원본의 `--hw`는 Apple VideoToolbox 중심이다. Windows에서 NVIDIA GPU 자동 가속 옵션으로 해석하지 않는다. 가속을 요청받으면 실제 지원 인코더와 프로젝트의 기존 설정을 확인한다.
- 기존 코드나 직접 FFmpeg 명령이 더 작고 적합하면 사용해도 된다. 이 경우에도 입력·출력·필터·인자를 실제 버전에서 확인하고 결과를 검사한다. 새 래퍼나 의존성을 만들 이유로 이 도구 묶음을 사용하지 않는다.

## 작업별 도구

표의 명령은 `scripts/` 아래 파일을 위 방식으로 실행한다. 나머지 도구·JSON 프로젝트 형식은 필요한 항목만 [전체 스크립트 참조](references/scripts.md)에서 찾는다. 이 설치는 CLI 도구 묶음이며 MCP 서버를 등록하지 않는다.

| User says | Do |
|---|---|
| 파일 정보·길이·트랙 확인 | `probe.py input.mp4` |
| 지정 구간 자르기 | `cut.py input.mp4 --start 1 --end 5 -o cut.mp4` — 프레임 정확도가 필요하면 `--accurate` |
| 여러 구간 남기기 | `cut.py input.mp4 --segments 0-3,5-8 -o cut.mp4` |
| 클립 단순 연결 | `join.py clip1.mp4 clip2.mp4 --transition none -o joined.mp4` |
| 세로 화면으로 변경 | `fit.py input.mp4 --aspect 9:16 --fit pad -o vertical.mp4` — crop·blur는 화면을 보고 선택 |
| SRT 자막 넣기 | `caption.py input.mp4 --srt subtitles.srt --lang ko -o captioned.mp4` |
| 제목·로고·자료화면 겹치기 | `overlay.py` 또는 `graphics.py`의 지원 형식과 위치 옵션 확인 |
| 음악·음성 결합 | `audio.py`에서 입력 트랙, 믹스·교체·덕킹 의도에 맞는 옵션 선택 |
| 음량 측정·조절 | `loudness.py` — 명시된 출력 목적과 실제 측정값에 맞춰 선택 |
| 여러 효과를 한 편집안으로 실행 | `render.py project.json` — 소규모 수정에 별도 JSON 프로젝트를 강제하지 않음 |
| 출력 규격 확인 | `check.py output.mp4 --platform youtube-shorts` — 해당 플랫폼 요청일 때만 |
| 바뀐 화면 확인 | `look.py output.mp4 --tiles 3x2` 또는 문제 시각 `--at` — 생성한 PNG를 직접 열기 |

## 손실·한글·오디오

- 단순 remux나 키프레임 컷은 가능하면 재인코딩을 피한다. 프레임 정확도, HDR, VFR, 트랙 동기화에 영향이 있으면 필요한 재인코딩을 적용한다. 중간 출력을 여러 번 압축하지 않는다.
- `join.py`는 옵션을 생략하면 0.5초 fade로 겹쳐 연결하므로 총길이가 줄어든다. 단순 연결·대사·TTS 구절 연결은 `--transition none`을 명시한다. 전환이 요청되면 겹치는 시간과 발화 보존을 고려해 선택한다.
- HDR·Log·가변 프레임률·동기화 문제가 있는 소스만 [기기별 주의점](references/devices.md)과 [처리 함정](references/gotchas.md)의 해당 절을 읽는다. 색 공간 메타데이터 변경과 실제 톤 매핑을 혼동하지 않는다.
- 한국어 자막은 UTF-8 텍스트, 실제 한글을 지원하는 폰트, 최종 화면 크기에서의 줄바꿈을 확인한다. `--lang ko`를 쓸 수 있고, `--font`를 지정하면 자동 폰트 선택을 덮어쓴다. 폰트 이름만 보고 글리프 지원을 확정하지 않는다.
- 승인된 대본·SRT와 실제 음성을 우선한다. ASR은 선택 기능이다. 기존 타이밍 자료가 있으면 재전사하지 않으며, 전사문을 사실·고유명사·최종 대본의 근거로 쓰지 않는다. 한국어 작업에 영문 전용 모델을 사용하지 않는다.
- 설치된 ASR 엔진이라도 모델 캐시가 없으면 다운로드를 시도할 수 있고, 일부 `--transcribe` 경로는 dry-run에도 실행된다. 모델·폰트·외부 생성 서비스는 요청 범위와 비용을 확인해 필요한 경우에만 준비하며 스킬 설치를 해당 동작의 승인으로 해석하지 않는다.
- 화면 크기 변경을 자막 합성보다 먼저 한다. 글자 깨짐·잘림·목소리와 어긋나는 자막은 출력 실패다. 텍스트 수정이 요청되지 않았으면 자막을 임의로 요약하지 않는다.
- 음성의 이해 가능성을 우선하고 음악·효과음이 발화를 가리지 않게 한다. 낮은 주변 소리를 음성 목표 음량까지 증폭하지 않는다. 음량 수치 측정과 실제 청취를 구분한다.
- 새 결과 경로로 저장하고 원본을 보존한다. 기존 파일 덮어쓰기 옵션은 그 파일을 교체하는 요청 범위에서만 쓴다. 자막·오버레이 등 부수 파일의 경로도 충돌하지 않게 잡는다.

## 출력 확인과 전달

구현 완료 후 종료코드, 결과 파일 존재·크기, 실제 길이·화면 규격·오디오를 확인한다. 쓰기 도구의 JSON에 이미 있는 측정은 재사용하고, 전달 목적에 필요한 디코딩·플랫폼 검사만 추가한다. `verified` 필드는 그 도구가 수행한 검사 범위이며 영상의 전체 품질 보증이 아니다.

화면이 바뀌면 해당 장면·자막 시각의 프레임을 열어 내용·잘림·가독성을 확인한다. 오디오가 바뀌면 음성 시작·끝과 접합 구간을 들어본다. 확인 수단이 없으면 그 부분을 미확인으로 남기며 검사 성공으로 대체하지 않는다. 수행한 검사가 통과하면 별도 리뷰·전체 재검사를 더하지 않는다.

결과 파일 링크, 주요 변경, 측정된 규격과 실제 수행한 검사, 남은 한계만 한국어로 간결하게 전달한다. 특정 영문 5줄 양식이나 내부 명령 로그를 강제하지 않는다. 렌더·저장과 공개 게시를 구분한다.
